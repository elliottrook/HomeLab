## Compressed 4K soak

A ten-minute 4K test deliberately excluded UHD Blu-ray, BDMV, ISO and remux
sources. The selected title was *Tow* (2026), a 3840×2160 iTunes WEB-DL in MKV:
HEVC Main 10, HDR10+, 23.976 fps, 25.29 Mb/s and 18.69 GiB. Jellyfin reported
`DirectStream` for all 21 samples and created no video transcode. Kodi used the
software `ff-hevc` decoder because Haswell exposes no HEVC VAAPI profile.

The requested 600-second run completed without pause or early termination:
599.2 seconds of media advanced in 600.0 seconds wall time. After initialization,
the render samples were normally 23.41–24.39 fps, with one transient 21.46 fps
sample that did not accumulate playback lag. Kodi consumed 166.5–331.4% of one
CPU core (roughly 1.7–3.3 of the four logical CPUs), stabilized around
1.01–1.06 GiB RSS and reached 81 °C. Temperature oscillated between 76 and
81 °C under sustained load and fell to 57 °C after stop. The kernel reported no
thermal throttle, hang, reset, fault or OOM. Kodi logged no decode/drop failure;
the only output-buffer timeout occurred at the deliberate stop boundary.

This proves a compressed ~25 Mb/s 4K HEVC WEB-DL can play in real time on the
M93p without burdening Jellyfin's transcoder. It is an upper-edge capability,
not general 4K parity: CPU and thermal headroom are limited, and disc-class
UHD/remux sources remain outside the accepted low-spec profile.

`/storage/.aster-checkpoints/astertv-jen-jellyfin-policy-20261104T195218Z`.

Jellyfin was already set to QSV but its hardware decoder list contained only

Jellyfin enabled those four decoders in addition to the existing two and

an observed trial failed closed because this container exposes no OpenCL

The same *Tow* source then produced a 1920×1080 H.264 QSV stream at 17.744 Mb/s
plus audio. The live command proved VAAPI HEVC decode, `scale_vaapi`,
`tonemap_vaapi` and QSV H.264 encode. Transcode speed rose from 5.3× to 15.2×
real time while FFmpeg CPU fell from about 1053% to 89–106% and container

continuous Transcode playback with no Kodi player/decode error before the
deliberate stop.

## Verdict

The M93p is a viable low-spec AsterTV client for the accepted v2 UI and real
1080p H.264/HEVC media. It is not a production-equivalent 4K client because
Haswell lacks HEVC/VP9/AV1 hardware decode. Production backend parity is now
proven for Jellyfin, Books/Audiobookshelf, Seerr discovery/acquisition, Home
delivery, cameras and read-only eBooks; YouTube is deferred and the new v3
Aster AI route remains correctly blocked on a search-only identity/contract.
Initial full Music synchronization is the largest observed load and is the
first feature to reconsider if the eventual low-spec profile needs trimming.
With the News lifecycle repair and Jen-only Jellyfin policy, the machine is a
viable stable low-spec AsterTV candidate for the complete tested feature set.
Its local acceptance envelope remains 1080p H.264/HEVC; 4K HEVC is deliberately
converted by the server to 1080p H.264 instead of being decoded locally near
the CPU and thermal ceiling. Rapid automated plugin opens still need
asynchronous test handling, but no tested feature now needs removal for cleanup
or resource stability.

The final durability pass rebooted the host twice. Key-only SSH returned,
password authentication remained disabled, all six credential/key files were
mode `0600`, Kodi/camera/Books timer were active, both NFS automounts remounted
read-only on access, the 63-entity Home feed remained present and the 528-file
accepted-release guard verified with zero drift. All temporary screenshots and
credential staging files were deleted.
