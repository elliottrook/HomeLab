# M3 9B/SYCL compatibility — first bounded run

**Decision: v1 fails its engineering interface threshold.** It does not
qualify the local model for automatic routing, disqualify it for ordinary
answers, or compare its quality with Codex. No tool, permission or production
configuration changed.

Jason authorized preparing and running this synthetic test while the B60 was
mostly idle. The run used the [frozen card](RUN-CARD.md) and the pinned 30-case
development fixture. The runner was sent over SSH stdin and executed as the
existing `ollama` account inside LXC 110. It read the pre-existing mode-0600
inference API-key file *inside that container*; the key was never printed,
placed in a command argument, model message or retained result. There was no
remote file installation. Five local mocked tests passed before the live call,
covering fixture transport, valid output, stop-on-first-invalid, HTTP errors,
and exclusion of the key and request text from results.

Read-only preflight found `aster-llama.service` active with MainPID 7049 and
zero recorded restarts, `/health` OK, zero processing and zero deferred
requests at that instant, and no active `ai-lab` systemd unit. The service
unit SHA-256 was
`a4c75169673a1a230682b73d362a05c1bdd30f7a5c41cfb9c77463204dfd4cb3`;
the loaded 9B GGUF file SHA-256 was
`cd76ec205963b3b33350093e6904d9de16c4e666fd104e1f632d25c7f15f2a13`.
The runner and transport source hashes were respectively
`4a2b3ba0543562132d493951157ea6702c57454c72b3648391d1d1116e8629f9`
and `6c643553b4436c32703b0c92b0cac15ded8a0fc581b70ec1f544550402abe654`.

The first request, `timer-train`, returned an HTTP-successful response in
3.032 seconds, but its content failed the strict JSON/shape/capability parser.
The v1 runner records only `invalid_response`, so this result **cannot say**
whether the issue was non-JSON text, an unexpected JSON shape, a prohibited
capability or another parser mismatch. It deliberately did not retain raw
answer text. Per the card, execution stopped after **one** request; there was
no retry of that case and no latency percentile. The retained content-free
[result](run-v1-2026-10-12.json) has SHA-256
`f45f51a1f0e69048c2de9cfae73ef6f4a86185d9b1370a6b7da47953400c95db`.

Post-run, the same service remained active at PID 7049 with zero restarts,
`/health` OK, and zero processing/deferred requests. Prometheus cumulative
token counters increased by more than this runner alone can attribute, so
the pre/post snapshots do not prove exclusive use or per-request token cost.
No latency or quality comparison is made from them.

**Next bounded hypothesis:** instrument a *different* synthetic case with
content-free parse-stage diagnostics and a fixed response hash to distinguish
transport, finish/truncation, JSON syntax and schema mismatch. Version its
card and source before a new call. Do not rerun `timer-train` under v1 or
silently loosen the v1 parser. If that diagnostic identifies a correctable
interface problem, a new versioned 30-case run may be considered; the
representative human-labelled quality gate remains separate.
