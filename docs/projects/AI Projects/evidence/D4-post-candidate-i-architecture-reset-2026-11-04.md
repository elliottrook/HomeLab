# D4 post-candidate-i architecture reset — 2026-11-04

## Decision

Candidate-i is rejected and closed. This reset uses only its aggregate frozen
decision: 8/20 complete-intersection passes, 0/6 mandatory abstentions passing,
and zero false-completion failures. It does not inspect or tune against
per-case judgments, prompts, answers or answer keys.

Candidate-j is a materially different source-only direction. Instead of asking
the model to author final diagnostic prose, it permits a future model to select
at most two IDs from a case-specific registered hypothesis set. Deterministic
code validates current evidence support, renders every fact, uncertainty,
scope and verification sentence, and owns outcome, checks, effects and
authority. Secret, stale, unavailable, malformed or unsupported paths abstain
with registered actionable checks and assign no cause.

## Frozen source boundary

The first contract validates exact capability, observation, freshness and
hypothesis cross-references. A selected hypothesis must be preregistered and
supported by current usable observations; the model cannot add prose, checks,
effects or authority. The deterministic renderer labels every claim as a
hypothesis, preserves literal non-completion and requires verification before
cause assignment.

The focused source suite passes 5/5. It covers deterministic bounded rendering,
model-field injection, secret and stale abstention, unsupported selection, and
schema/cross-reference/unsafe-claim drift.

## Next untouched boundary

This is not a candidate release or authority to run. Before any model request,
candidate-j still needs a strict selection-only runner, a separate public
development fixture, a source freeze, and an independently created untouched
quality packet that does not reuse candidate-g or candidate-i evaluation
cases. The quality bar remains conservative; no threshold is lowered and no
automatic route, repair authority, tool grant or model/backend change follows.
