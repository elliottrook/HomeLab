# A1 — offline completed-answer capture and review candidate

**Status:** Development-only, 2026-10-12. No model call, live tool, private
request, lab lease, cloud consent, production route or permission change.

The six-case [synthetic fixture](../../../../scripts/aster-adaptive/fixtures/answer-feasibility-v0.json)
already defines public fictional requests and human-readable rubrics. The
new `capture_answer_feasibility.py` accepts one attempt per fixture case,
checks the fixture digest, disabled-tool mode, source IDs, terminal state and
bounded timing, and emits a content-free summary. Completed answers remain in
the input artifact; the summary contains only byte count, timing, status,
source IDs, error category and a `human_review: pending` marker. Failures and
abstentions are retained rather than removed from latency or quality review.

`score_answer_feasibility.py` accepts a separate human review tied to the exact
capture summary digest. It requires a judgement for every rubric item and
prohibited-claim item, plus source attribution. It rejects a failed attempt,
any missed rubric item or any prohibited claim as a pass. It emits per-case and
per-class development counts without answer text. This is an explicit review
calculation, **not** an automated semantic judge or a qualification result.
The labels themselves still require independent, blinded adjudication before
they can support a release decision.

The input and review JSON schemas are enforced by the two standard-library
scripts. For local development, invoke them as:

```sh
python3 scripts/aster-adaptive/capture_answer_feasibility.py FIXTURE.json ATTEMPTS.json > CAPTURE.json
python3 scripts/aster-adaptive/score_answer_feasibility.py FIXTURE.json CAPTURE.json REVIEW.json > SCORE.json
```

Keep any future raw real-interaction answers outside Git under separately
approved restricted custody. This v0 candidate accepts only the named public
synthetic fixture class and is not a privacy certification for other inputs.
The `attempts_sha256` proves which input bytes were projected; it is not a
claim that those bytes were generated by a named backend. A later runner must
bind the candidate manifest, invocation and capture to the observed output.

Focused tests: 13 passed for fixture validation, capture projection and
review scoring. They cover duplicate/missing cases, scope mismatches, unknown
source IDs, false completion, malformed timing, prohibited claims, failed
attempts and stale/incomplete review records. No answer-quality test has run;
no quality floor, latency budget or lab card is READY. The next useful step is
an offline synthetic runner/postcheck and independently reviewed answer labels,
then a preregistered current-control measurement plan. A1 remains blocked for
exclusive execution until its candidate and verified shared lease exist.
