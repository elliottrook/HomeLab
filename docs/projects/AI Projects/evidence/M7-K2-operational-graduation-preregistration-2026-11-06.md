## Required graduation evidence

The boundary is reachable only after M6 emits a non-authorizing
`promote-readonly-candidate` decision. It then requires two independent normal
operator passes, distinct attempts and request sets, separate Lab Hours
bookings whenever B60 is used, zero retries and safety/privacy failures,
production restoration after each pass, and one explicit degraded/fallback
recovery pass with no false completion. Temporary state must be absent,
monitoring and Doctor healthy, limits documented and owner acceptance explicit.

The role remains bounded read-only investigation routing. It excludes tools,
repair effects and personal-data cloud egress; keeps the existing deterministic
or local fallback; and retains a 45-second candidate latency ceiling.

## Separate gates retained

- any service restart: explicit approval;
- fixed-root installation: separate effect gate;
- automatic-routing activation: separate release gate;
- tools or repair: outside this boundary.

The focused suite passes 4/4 and syntax compilation passes. This source work
created no booking, runtime effect, deployment, route or model request. It also
produces no UI or spoken output, so no design or Aster voice change is involved.
