## Safety and recovery decision

Forgejo's [v15 mirroring documentation](https://forgejo.org/docs/v15.0/user/repo-mirror/) says push mirrors may force-push remote refs, and an existing push mirror cannot simply be switched to Forgejo-managed SSH authentication. Its [configuration documentation](https://forgejo.org/docs/v15.0/admin/config-cheat-sheet/) says migration URL restrictions also apply to push mirrors. Therefore, neither recreating the mirror nor relaxing a global allowlist is a routine retry. A direct GitHub push is excluded by the repository rule unless Jason explicitly requests mirror recovery.

The supported UI inspection establishes the URL, exact error, interval and blank branch filter. The Git user's alias SSH profile authenticates, but whether the mirror invokes that profile is unproven because URL validation stops first. Preserve that unknown as a recovery gate, not an assumption. The non-PR branches and tags have now been compared read-only. Compare two bounded repair candidates:

1. Use a canonical `github.com` SSH URL with a repository-scoped Forgejo-managed SSH mirror key, a verified GitHub deploy key, strict host-key checking, the existing blank branch filter and eight-hour interval. This requires mirror replacement and a separately reviewed credential/remote-write/force-push gate. The existing alias key must remain until the replacement proves healthy; then revoke it as a separately verified step. Do not silently rely on the weaker ambient `github.com` SSH configuration.
2. Explicitly permit only the existing alias under Forgejo's URL policy if the installed implementation supports it and the change does not broaden or break other mirrors. Validate that the alias still resolves only to the intended GitHub host. A global allowlist change is not assumed safe.

Before either change: determine the existing authentication path without reading secrets; verify the target repository, key ownership and host-key policy; document rollback to the previous mirror configuration. Preserve the blank branch filter and 8-hour interval unless explicitly reviewed. Do not treat provider-owned `refs/pull/*` as a mirror target. After a specifically approved repair: run one sync and verify the exact GitHub SHA and no unexpected named branch or tag changes. Until then, mark protection-mirror synchronization **FAILED/PENDING** while Forgejo remains the sole authority.
