# D4 candidate-i deterministic-verification source boundary — 2026-11-04

Candidate-g is closed at its spent 10/20 blind quality result. Candidate-i is
a materially different source-only architecture: the model may draft only a
bounded diagnosis for usable-evidence plans. Deterministic code owns outcome,
checks, effects, authority and the entire verification instruction. Secret,
empty and unavailable-evidence paths are fully deterministic and make no model
call in the future runner design.

Every summary now has an explicit `Verification:` clause. For a plan, it names
only the already selected registered sources and requires their state and
freshness to be refreshed before cause. For an abstention, it requires a
bounded symptom and one approved current non-secret source. False-completion,
secret-bearing, malformed or expanded model output falls back to deterministic
diagnosis text and cannot alter verification or controls.

Four tests pass against the existing public development fixture. They cover
all 12 public cases, fixed controls, attempted verification/control injection,
the three deterministic abstention classes and unsafe diagnosis fallback.
Candidate-i is not yet frozen or runnable. It has no quality packet, booking,
model call, route, authority or promotion; the next source milestone is an
exact candidate manifest plus a new untouched evaluation boundary.
