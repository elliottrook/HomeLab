# Forgejo and NetBox source-report reader boundary — 2026-10-11

**Status: narrow live reader hardening deployed and postchecked.** The source producers, Forgejo/NetBox instances, credentials, broker grants and Codex tools were not changed.

The shared Aster reader for the existing sanitized Forgejo and NetBox reports used `lstat()` followed by a separate `read_text()`, leaving a file-replacement race after validation. It also interpolated OS read errors into an assistant-visible response, which could disclose the report path. A JSON array/object in a Forgejo repository `visibility` field could raise `TypeError` instead of returning the defined `unavailable` result. No production occurrence of malformed data was established; these were source-level fail-closed defects.

The local candidate opens once with no-follow/nonblocking flags, validates the opened descriptor's type, owner, permissions and size, bounds the read, returns fixed OS/decoder errors, and checks visibility type before set membership. Synthetic missing-path and malformed-visibility regressions were added. The source-report, ARR, HA and gateway suite passed 124 tests; `git diff --check` passed. A read-only comparison showed the installed source differed only by these candidate edits. Before replacement, the installed SHA-256 was `387331f935bb3e51fcd47bf1600e159cb616ee9a7b98e4cb5edbda2bb2bf25d4`.

**Risk and rollback:** only LXC 104's `/opt/aster-agent/source_reports.py` and one Aster gateway restart were in scope. The old root-owned mode-0644 file remains at `/opt/aster-agent/rollback-source-reports-before-parser-20261011.py`. An exact old/new hash precondition guarded an atomic replacement; a restart or health failure would have restored the old file. The deployed SHA-256 is `7a85c52a5b350f3dde81b52fdd118f9a37f9a45feaca50db4f86092a297eadd2`.

Before and after the swap, source-local calls as `aster` validated the existing reports without printing their contents. The Forgejo report had one repository, and the NetBox report had five inventory categories. A staged candidate rejected a synthetic malformed visibility. Independent postchecks found Aster active/running with zero recorded restarts, `/health` OK, both reports available, and a missing Forgejo report yielding `unavailable` without its private basename. These prove immediate reader behavior, not long-term producer reliability or model answer quality.
