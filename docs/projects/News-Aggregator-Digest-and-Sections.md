## Purpose and desired outcome

Phase 1 delivered an hourly "breaking news" clustered feed. Jason asked for
three additions on top of it, without disturbing the breaking-news view:

1. A twice-daily (06:00/18:00) richer digest per cluster: an **abridged,
   multi-source synthesis** plus, for multi-outlet clusters, **deviation
   notes** — what one source says that the others don't — generated by the
   same `aster-llama` endpoint and dedicated key Phase 1 already uses.
2. A redesigned card layout for that digest view specifically (hero image
   when the feed provides one, outlet-badge header when it doesn't, styled
   after the Apple News "Top Stories" card Jason shared), while the existing
   breaking-news view stays exactly as it is today.
3. A settings page where Jason can request a new source, or a whole new
   **section** (e.g. "add a photography section with these sources") —
   queued for the same live-verification pass every feed has gotten since
   Milestone 2 of Phase 1, not auto-added to `feeds.json` unverified.

Explicitly out of scope for this phase (Jason's own words): scraping outlet
pages for better photo coverage stays deferred to a possible Phase 3, not
built now.

## Pre-start risk assessment and authorization envelope

- **Objective and scope:** the three items above, built on the existing
  LXC 114 guest, existing SQLite database, and existing `aster-llama`
  credential. Allowed changes: new tables in the existing `news.db`, a new
  `digest.py` pipeline stage, a new systemd timer/service pair, new Flask
  routes and templates in the existing `app.py`, and structured `section`
  fields in `feeds.json`. No new guest, no new credential, no new inbound
  exposure, no new outbound egress target beyond `aster-llama` (already
  permitted, same VLAN) and the RSS/Atom feed URLs Jason approves through
  the settings-page queue.
- **Affected systems:** LXC 114 only. No firewall, DNS, NetBox, or
  Homepage change is anticipated — nothing new is being exposed or
  relocated. HomeLab Doctor's existing `check_news_aggregator()` will be
  reviewed for whether it needs a digest-specific addition, not replaced.
- **Non-waivable stop condition preserved:** see the checkpoint above (a
  requested source with no clean feed).
- **Backup:** already covered automatically — Phase 1's whole-guest backup
  (local Proxmox snapshot plus the checksum-verified TrueNAS off-host pull)
  captures the entire LXC 114 filesystem, so new tables in the same
  `news.db` and new files under `/opt/news-aggregator/` need no separate
  backup step.

## Milestone 1 — Data model and schedule

- [ ] Add a `section` field to every entry in `feeds.json`, backfilling
      Phase 1's 10 existing feeds into the categories Milestone 1 of Phase 1
      already used in prose (general/world, tech, local) but never
      structured as data.
- [ ] Add `image_url` (nullable) to `feed_items`, populated by `ingest.py`
      when a feed entry provides `media_thumbnail` or an image enclosure —
      confirmed live that only 1 of the 3 largest current feeds (BBC)
      actually provides one; NPR and Al Jazeera provide none. No article-page
      scraping for a better hit rate — out of scope per Jason's own call.
- [ ] Create `digest_entries` (cluster_id, abridged_summary, deviation_notes
      nullable, image_url, digest_run, generated_at, model) — kept separate
      from Phase 1's `cluster_summaries` so the digest layer can never affect
      the breaking-news view.
- [ ] Create `source_requests` (id, requested_name, requested_url, section,
      is_new_section, note, status, requested_at) — a queue, not a
      write path into `feeds.json`.
- [ ] Add `news-aggregator-digest.timer`/`.service` at 06:00 and 18:00,
      matching the existing timer's `RandomizedDelaySec`/`Persistent=true`
      pattern. The existing hourly `news-aggregator-ingest.timer` is
      untouched.

## Milestone 2 — Digest synthesis pipeline

- [ ] `digest.py`: for each cluster touched since the last digest run,
      generate an abridged multi-source summary for every cluster, and
      deviation notes for clusters with 2+ outlets only (nothing to deviate
      from with a single source).
- [ ] Bound how much per-outlet text enters the deviation prompt —
      `aster-llama` has one 8,192-token inference slot (per
      `Aster-Operations.md`); do not assume headroom, measure it against a
      real multi-outlet cluster.
- [ ] Idempotent and independently failing, matching `run_pipeline.sh`'s
      existing convention.
- [ ] Verify against real data: run against genuine multi-outlet clusters
      from the live corpus, spot-check that deviation notes name a real,
      checkable difference between sources rather than a plausible-sounding
      but ungrounded claim — the same standard Phase 1 held `language_notes.py`
      and `summarize.py` to.

## Milestone 3 — Digest UI

- [ ] New `/digest` route and template: hero image when `image_url` exists,
      an outlet-badge header (styled like the Globe and Mail card in Jason's
      reference screenshot) when it doesn't, headline, contributing-outlet
      byline with ratings (reusing Phase 1's tooltip pattern), and the
      deviation notes surfaced as a distinct callout, not buried in body text.
- [ ] The existing `/` breaking-news view is verified pixel-for-pixel
      unchanged after this milestone — a regression check, not an assumption.

## Milestone 4 — Settings and source-request page

- [ ] New `/settings` route: a form to submit one source (name, URL,
      existing or new section) or several sources at once under one new
      section name. Writes only to `source_requests`.
- [ ] A simple pending-requests list on the same page so Jason can see what's
      queued without opening the database directly.
- [ ] Explicit regression check: submitting a request never modifies
      `feeds.json` — verified directly, not assumed from the code path.

## Graduation criteria

The project graduates when the digest generates real, verified (not
assumed) abridged summaries and deviation notes on schedule, the digest UI
renders correctly with the documented image fallback, the breaking-news
view is confirmed unchanged, the settings page correctly queues requests
without touching `feeds.json`, and HomeLab Doctor passes cleanly.
