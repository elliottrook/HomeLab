# Media SSO compatibility assessment

Assessed 2026-09-23 for the approved Stream A Authentik rollout. This is a
read-only production assessment and local artifact/source review, not a
production deployment or completed end-to-end compatibility test.

## Decision

- **Jellyfin:** target the 12.x generation rather than adding a retiring 10.11
  SSO dependency. Jellyfin 12.1 is already stable; there is no need to wait for
  the server's beta to finish. Prefer waiting for the plugin's 5.1 improvements
  to reach stable and pass a local isolated rehearsal before production SSO.
  A separate server upgrade to 12.1 can be evaluated first; SSO need not hold
  back core security updates indefinitely.
- **Seerr:** retain stable 3.4.1. Evaluate OIDC in an isolated preview only; do
  not replace production with an unmerged authentication feature merely to
  remove its password prompt. Reassess on an upstream stable release carrying
  OIDC or after an explicitly accepted preview risk and successful rehearsal.
- Do not use a shared API key as a browser impersonation bridge. A forward-auth
  wrapper alone does not meet the requested single-login experience.

## What Jellyfin 12 and the beta add

[Jellyfin 12](https://jellyfin.org/posts/jellyfin-release-12.0/) brings database,
playlist and collection improvements, expanded books/comics support and security
fixes. Its release does not establish built-in Authentik OIDC; the assessed
single-login path still uses a plugin. [12.1](https://github.com/jellyfin/jellyfin/releases/tag/v12.1)
adds migration/backup, playback and session-related fixes.

The pinned 5.1 beta source contains `PreserveUnmanagedFolders`; 5.0 stable does
not. When enabled, it preserves library grants outside the provider-managed set
instead of replacing every folder assignment at login. This matters for mixed
family accounts and manually managed libraries, but does not preserve all
permissions automatically or eliminate the need to review role mappings.

The beta also adds a one-use, one-minute logout ticket, avoiding a long-lived
session token in URLs generated by its self-service logout UI. Ordinary Jellyfin
sign-out remains distinct from IdP-wide logout. Its notes describe a remaining
multi-session nuance: the IdP logout hint can refer to the newest provider
session rather than the exact local session being ended. Neither version may
be assumed to provide perfect global logout without explicit testing.

[5.0 stable release notes](https://github.com/Flowfin/jellyfin-plugin-sso/releases/tag/5.0.0-JF12-stable)
report provider-matrix runs and iPhone/Apple TV checks, but explicitly omit
reverse-proxy forwarded-header attribution, an in-place plugin upgrade check
and Android-pair manual testing. Its changelog records a canonical-provider test
on server 12.1. These are upstream results, not HomeLab acceptance.
See the [pinned beta changelog](https://github.com/Flowfin/jellyfin-plugin-sso/blob/5.1.0-JF12-beta.98/CHANGELOG.md)
for the improvements above. A stable 5.1 date is not verified; waiting should be
based on release status and passed gates, not an invented ETA.

## HomeLab account and client implications

Read-only SQLite summaries found six Jellyfin accounts and no case-folded
username collisions, removing one documented 12.x migration hazard. Both
`jason` and `elliottrook` are existing administrators and have recent activity.
**Do not infer which account should receive the Authentik owner link from its
name.** Confirm the intended account and bind its existing UUID explicitly;
preserve the other account and all family accounts. No account was linked,
renamed, merged or disabled during this assessment.

Persisted device records include Jellyfin Web, Android TV, Swiftfin tvOS,
Moonfin for tvOS, Streamyfin, JellyTV, JellyAmp and Seerr. These are historical
registered clients, not proof every device is currently used. Quick Connect is
already enabled. Browser SSO can use Authentik passkeys; compatible native/TV
clients generally need a Quick Connect code approved from an authenticated
browser. This is not Face ID embedded in every native application.

Flowfin's SSO-only switch repoints authentication providers for non-exempt
accounts, retaining one recovery administrator. It is not merely a hidden login
form. Do not enable it across these six accounts for an owner-only pilot. First
verify owner linkage, family login paths, client tokens, permissions, playback
and recovery. Public auto-provisioning is not needed for this household rollout.

The [Ezeqielle migration guide](https://github.com/Ezeqielle/jellyfin-plugin-oidc/blob/v1.0.10/MIGRATION.md)
describes matching by username, rewriting role/library permissions on each SSO
login and re-enabling disabled accounts. Its existing-user password fallback
remains. These behaviors make it a less attractive first candidate for this
requirement than explicit stable-subject linking and a tested policy-preserving
Flowfin configuration. This is a suitability judgment, not a full security audit.

## Seerr assessment and Jellyfin 12 interaction

Production has two users and 76 request rows. The owner is existing user ID 1;
its local username is null and it is media-server-backed. Do not create a new
local account based on `preferred_username` and abandon that request history.

The [pinned OIDC proposal](https://github.com/seerr-team/seerr/pull/2715) supports
explicit linking to the signed-in existing account, PKCE/state, a unique
provider/subject link, and disabling new-user creation. Its SQLite migration
adds `linked_accounts`; it does not itself migrate existing identities. A pilot
would use `newUserLogin=false`, owner-only Authentik policy and an explicit link
to ID 1. Callback routes are browser `/login` and
`/profile/settings/linked-accounts`; its initiation returns a JSON redirect URL,
so a simple NPM redirect to the API endpoint is not an automatic-login solution.
Full automatic browser launch must be verified separately.

A concrete cross-version issue emerged from source inspection:

- Seerr 3.4.1's main Jellyfin API class uses `Authorization: MediaBrowser ...`.
- Its logout device-deletion request still uses `X-Emby-Authorization`.
- Jellyfin 12.1's authorization parser only accepts that legacy header when
  `EnableLegacyAuthorization` is enabled; the 12.x migration disables it by
  default.

Therefore that logout cleanup path is expected to fail under the default 12.x
configuration, even though the main API class uses the current form. This is a
source-derived prediction, not a reproduced runtime failure. The reviewed OIDC
PR retains the same legacy logout path. A supported fix or bounded verified
compatibility strategy is required before cutover; do not broadly re-enable
legacy authentication as a default shortcut. Test local Seerr logout and actual
Jellyfin device/session revocation separately.

## Recovery and next bounded test

Jellyfin's real `/config` is the named Docker volume, approximately 12.8 GiB;
`/mnt/Media/appdata/jellyfin` is mounted at `/appdata` and is not its authoritative
configuration. Retain current image ID
`sha256:e969610cc5104c4a806d30921b86027bdbf4149dc1490b756e60c1187bf38169`.
Seerr's real config is `/mnt/Media/appdata/seerr`; retain image ID
`sha256:8921315d8f128b2c159abadee7733ec63dc16f46c2e6f56d9a57d7db3470f36a`.
These are observed local image identifiers, not remote pullable digest claims.

Jellyfin 12 rewrites its database on first boot and requires a full library
scan. Rolling back an image alone is unsupported: restore the full pre-upgrade
configuration/data and original image together. This assessment created no full
production checkpoint and did not test restore. Plugin configuration, identity
links, encrypted-secret keys and user authentication-provider changes must all
be included if SSO has been enabled. Simply deleting the plugin is insufficient
for accounts whose native authentication provider has been changed.

Recommended rehearsal, before requesting any production cutover decision:

1. Capture a verified stopped-service full Jellyfin config/data checkpoint and
   exact container/Compose metadata. Take Seerr's consistent database/settings
   checkpoint separately. Keep media outside the archive and unchanged.
2. Run a copy of Jellyfin 12.1 with private test-only access and media read-only.
   Preserve production untouched; isolate discovery/outbound activity and
   prevent duplicate jobs. Validate migration, library scan, users, watch state,
   permissions and restoring the copy to 10.11.11. Resolve and pin the actual
   LinuxServer 12.1 artifact before starting; its digest was not assessed here.
3. Test pinned SSO candidates on the copy with a separate test Authentik client
   and exact callbacks. Compare 5.0 stable and 5.1 beta for existing-account
   linking, folder preservation, denied identities, NPM headers and logout.
4. Rehearse Seerr preview separately with outbound ARR/download/notification
   actions blocked. Prove existing owner/request preservation and restoration;
   verify its complete login/link/callback and cross-version logout behavior.
5. Obtain real-device evidence for the actually used TV/mobile apps and owner
   identity choice. Disable no family password paths during the pilot.
6. Promote only a tested, pinned stable combination, or present the concrete
   preview exception and remaining risks for a separate decision. No calendar
   promise or background monitoring was scheduled.

Assessment complete. Production containers, authentication settings, DNS,
firewall rules and account data were unchanged. Full runtime/recovery and human
client acceptance remain prerequisites, not claimed results.
